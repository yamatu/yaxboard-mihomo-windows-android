# 变更记录（循序渐进维护）

目的：让每次修 bug/改功能都有“可追溯的上下文”，方便后续继续改、也方便 AI 理解历史决策。

## 规则
- 每次有“会影响行为”的修改（bugfix/功能/重构/配置语义变更），都新增 1 个 md。
- 文件名建议：`YYYY-MM-DD-<slug>.md`
  - 例：`2026-01-23-fix-remote-config-jsonc.md`
- 内容要写“为什么/影响/验证方式”，不要只写“改了哪些文件”。
- 如果变更涉及用户配置、协议或后端约定：必须在变更记录里写清楚兼容性与回滚方式。

## 模板
直接复制：`docs/changes/0000-template.md`
